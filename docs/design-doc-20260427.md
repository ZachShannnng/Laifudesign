## Problem Statement

公司设计师/PM在原型设计和高保真设计方面仍在使用Axure和Sketch等传统工具，效率低。同时，开发人员在Vibe Coding时无法有效应用公司的设计规范，导致前端产出效果不一致。需要一个AI驱动的设计工具，让设计师能快速基于公司设计系统生成高保真原型，并作为开发团队的统一输入源。

## Demand Evidence

- 公司已有完整的设计规范，但开发人员在Vibe Coding时无法直接应用
- 多个开发人员基于不同开源框架做前端，产出页面风格不一致
- Zach（PM）希望先通过自己出原型，再让开发按原型实现，而不是让开发直接根据需求开发
- 当前工作流（Axure + Sketch）效率低，且无法有效传递设计规范给开发

## Status Quo

设计师使用Axure做交互原型，Sketch做视觉设计。两套工具之间没有有效的设计系统约束传递。开发人员拿到需求后自行选择前端框架和组件库，产出与设计稿不一致。整个流程断裂在设计→开发这个环节。

## Target User & Narrowest Wedge

**目标用户:** Zach（PM/设计师角色）以及公司内部其他设计师。他们需要快速产出高保真原型，并确保所有产出遵循公司设计规范。

**最小可用版本:** 一个能通过自然语言描述生成单个页面高保真原型的工具，AI生成时自动遵循预设的设计系统规范，支持导出为静态HTML。

## Constraints

- Mac桌面应用（底层可用Web技术: Tauri/Electron）
- 不从零构建，基于开源项目OpenUI改造
- AI提示词尽量直接复用Claude Design的系统提示词（侧重原型制作和高保真效果图部分），但剥离其中的具体设计系统规范，改为运行时从用户配置的设计系统中动态注入
- 不需要Sketch式矢量编辑功能
- 不需要视频编辑、PPT生成、代码部署功能
- 设计系统管理是工具的内建功能，不是外挂
- MVP只做单页面，多页面管理推迟到验证之后

## Premises

1. 核心产品是AI驱动的高保真原型设计工具，设计师用自然语言描述需求，AI生成可视化页面原型，可继续迭代
2. 设计系统是工具的内建功能，包含样式变量（颜色/字体/间距/阴影/圆角）、设计组件和范例页面，AI生成时自动遵循
3. 输出物是高保真原型（静态HTML），用于给开发团队作为参考实现
4. 专注做设计，不做视频/PPT/部署
5. Mac桌面应用，底层可基于Web技术

## Approaches Considered

### Approach A: OpenUI改造（已选定）

**基座:** wandb/openui (~22K stars)

OpenUI已有: 自然语言→实时HTML流式预览、元素点击批注、版本历史、框架导出（React/Vue/Svelte）。渲染模型是iframe直接注入HTML，轻量快速。

2. 新建设计系统管理模块（颜色、字体、间距CRUD）
3. Tauri桌面壳包装
4. 导出为静态HTML
5. （MVP之后）多页面项目管理、组件库管理、设计系统导入导出

Effort: M (MVP 6-9周)

## Recommended Approach

**方案A: OpenUI改造**

选择理由:
- 核心体验（说一句话→画面出来）已经调好，不需要从零调试AI→预览的管道
- 架构简单（React + Jotai + iframe），容易理解和改造
- 流式渲染体验好，设计师能看到页面逐步构建
- 改造重点可以放在最重要的新功能上: 设计系统管理

### 核心模块拆解

#### M1: AI引擎改造（核心，优先级最高）

**目标:** 复用Claude Design系统提示词的核心部分（专家设计师角色、原型和高保真设计流程、HTML输出规范），剥离其中的具体设计系统描述，改为运行时从用户配置的设计系统动态注入

**提示词架构:**

系统提示词由三部分组成:
1. **Claude Design提示词核心（固定，从Claude-Design-Sys-Prompt.txt提取）:**
   - 专家设计师角色定义
   - 高保真原型设计流程（需求分析→结构规划→视觉设计→交互实现）
   - HTML输出规范（使用React+Babel运行时、Starter Components、CSS变量、全局样式规则）
   - 内容设计指南（排版、图片、交互）
   - 剥离: 删除提示词中内嵌的具体设计系统规范和品牌指南，这些改为运行时注入

2. **设计系统约束（动态注入）:** 每次AI调用时，将当前用户配置的设计系统（样式变量 + 组件规范 + 范例页面代码）注入到提示词中。示例:

```
你当前使用的设计系统规范:
<style>

    --primary: #1a73e8;
    --secondary: #5f6368;
    --background: #ffffff;
    --text: #202124;
    --border: #dadce0;
    --radius-sm: 4px;
    --radius-md: 8px;
  }
</style>
组件规范:
- 按钮: padding 8px 16px, border-radius var(--radius-md), font-weight 500, background var(--primary), color white
- 输入框: padding 8px 12px, border-radius 6px, border 1px solid var(--border)
- 卡片: padding 16px, border-radius 12px, shadow 0 4px 6px rgba(0,0,0,0.07)
范例页面参考（遵循此风格）:
[范例页面的HTML代码片段]
你必须严格遵循以上设计系统规范生成页面。
```

3. **输出规则（固定）:** 沿用Claude Design的输出格式（`<body>`内容、React+Babel运行时、内联CSS/JS）

**关键改造点:**

#### M2: 设计系统管理（最重要且最大的新模块）

**目标:** 设计师可以在工具内创建和管理完整的设计规范（样式变量 + 设计组件 + 范例页面），AI生成时自动遵循。预置shadcn UI作为基础模板。

**三大板块:**

**板块1: 样式变量**
- **颜色管理:** 主色、辅色、背景色、文字色、状态色（成功/警告/错误）的增删改。使用颜色选择器（Color Picker）+ Hex输入
- **字体管理:** 字体族选择（下拉列表）、字号阶梯（h1-h6、body、caption）、字重选择
- **间距管理:** 基础间距单位、间距阶梯（可视化显示间距大小）
- **圆角/阴影:** 预设的border-radius和box-shadow值

**板块2: 设计组件**
- 预置常用组件的样式规范: 按钮（主要/次要/幽灵）、输入框、选择器、卡片、表格、标签页、导航栏、面包屑、模态框、Toast通知等
- 每个组件定义: 尺寸变体（sm/md/lg）、颜色变体（primary/secondary/danger）、状态（default/hover/active/disabled）
- 组件规范同时注入AI提示词（自然语言描述）和预览iframe（CSS变量）
- 预置shadcn UI的组件规范作为默认值

**板块3: 范例页面**
- 预置典型页面作为AI的参考: 登录页、列表页、表单页、仪表盘、详情页
- 每个范例页面存储为HTML代码，AI生成新页面时会参考这些范例的风格
- 设计师可以把自己生成的满意页面保存为范例
- 范例页面的HTML代码片段会注入到AI提示词中作为风格参考

**为什么这三块都很重要:** 样式变量定义了"颜色和间距"，组件定义了"按钮长什么样"，范例页面定义了"整体布局和氛围"。三者组合才能让AI生成的设计真正符合设计师的自定义规范，而不是"大概用了正确的颜色但布局和风格完全不对"。

#### M3: Electron桌面壳

**目标:** 包装成原生Mac应用，设计师可以直接安装使用

- 使用Electron包装OpenUI前端
- 本地服务iframe内容（替换OpenUI的远程iframe URL `https://wandb.github.io/openui/index.html`）
- API Key管理: 使用Electron safeStorage或keytar存储用户的LLM API Key（macOS Keychain集成）
- 多模型支持: 用户选择服务商（智谱/zhipu、OpenAI、DeepSeek等）→ 输入API Key → 自动拉取可用模型列表 → 用户选择默认模型
- MVP不支持Claude API（国内无法使用）
- 应用菜单: 关于、偏好设置、导出
- 拖拽安装: 提供dmg安装包（electron-builder打包）
- **技术风险:** Electron体积较大（~150MB+），但渲染基于Chromium，与OpenUI的iframe+Babel渲染模型完全兼容

#### M4: 多页面项目管理（P2，MVP之后）

推迟到MVP验证之后。MVP只做单页面。

#### M5: 导出静态HTML

**目标:** 导出当前设计为可独立运行的静态HTML文件

- 单页导出: 导出当前页面为完整HTML文件
- 包含React+Babel CDN引用（unpkg.com），保持与Claude Design输出格式一致
- 包含设计系统CSS变量（`:root { --primary: #1a73e8; ... }`）
- 图片: 保留placehold.co占位图引用（不做图片本地化，那是P2的事）
- 交互行为: 保留生成的React组件和交互代码
- 导出的HTML需要联网查看（因依赖CDN），内部团队环境均有网络
- （P2推迟）项目导出、多页HTML文件集
